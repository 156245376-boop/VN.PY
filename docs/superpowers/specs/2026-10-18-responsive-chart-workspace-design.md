# 自适应布局与行情分屏设计

日期：2026-10-18（Asia/Shanghai）。
状态：用户已于 2026-10-18 确认设计及计划；产品代码已实施，最终验收记录见 `docs/chart-workspace.md`。
基线：`63fb433`，分支 `codex/research-paper-loop`。

## 1. 目标与现有问题

用户要求主窗口缩小时各区域不互相遮挡，并能按研究需要同时观察多个品种、多个周期。
2026-10-18 已确认采用单窗口多图工作区：单图、左右双图、上下双图、四宫格，
分隔条调整比例、每格独立设置、可选品种联动、单格放大、布局恢复、账户区集中显示。

当前结构有三个直接约束：

- `qf/web/style.css` 中外层行情网格虽使用 `minmax(0,1fr)`，内层 `.main-column`
  的隐式列和卡片仍受表格固有最小宽度影响；窄窗口中表格可越过预期区域，与右侧卡片重叠。
  修复需在真实窗口测量网格、卡片与滚动容器边界，不能仅用截断文字掩盖越界。
- `qf/web/app.js`、`qf/workbench.py`、`qf/market_session.py` 目前只维护一个选择、
  来源、版本和图表地址；后端切换品种或来源时会退出当前数据循环并重建 TqApi。
  直接复制 iframe 不能满足各格独立切换和更新。
- TqSdk 3.10.2 原生页面拥有自己的行情 WebSocket，并从本机 `/ws` 接收程序状态。
  多个 iframe 不是一条行情连接；免费权限、并发连接与各格数据就绪需据实际结果验收。

本次交付是更可靠的行情研究界面，不增加策略、委托或账户执行控制。
原有数据完整性、中文名称、单位、画线编辑和退出确认均需继续有效。

## 2. 方案选择

| 方案 | 收益 | 代价与结论 |
| --- | --- | --- |
| 单窗口、多原生图表视图，共用一个后台行情会话 | 保留天勤图表、已有历史与画线适配；便于多周期比较 | 需要隔离每格状态并验证原生连接；采用 |
| 每格创建独立 Python/TqApi 会话 | 后台隔离直接 | 重复认证、资源和生命周期更多，不作为首选 |
| 更换图表组件、自行重做行情绘制 | 可自由布局 | 需重新验证历史导航、价格轴、画图和数据口径，当前不采用 |

不升级 SDK、不修改安装包资源，不恢复封存架构。
适配以本机锁定的 SDK 源码和实际行为为准，不宣称原生支持未验证的分屏 API。

## 3. 主窗口布局

### 3.1 首页与行情列表

- 修正 workspace、网格列、卡片、搜索框等容器的收缩边界，确保 `min-width:0` 的约束逐层有效。
- 行情表格保留有意义的列宽，只在表格容器内横向滚动；表头、行和底部分页属于同一卡片。
- 内容区容纳不下行情列表和侧栏时，自选与新闻卡片移动到下方；断点按内容宽度验证，
  不只考虑屏幕物理分辨率。页面允许纵向滚动，不允许行情行穿过其他卡片。
- 登录、欢迎、图表操作栏在空间不足时换行，按钮与说明不互相覆盖。
- 左侧导航保持可访问；高度不足时可自身滚动，底部设置与说明不压住上方导航。
- 图表工作区放在行情列表与侧栏组合区的下方，使用整个内容宽度，避免四屏被侧栏进一步挤压。

### 3.2 图表工作区

顶栏提供布局选择、品种联动开关、当前活动格名称和放大工作区入口。
各格有固定编号和明显的活动边框；点击图内或该格标题栏都可激活该格。

| 布局 | 可见格 | 分隔条 |
| --- | --- | --- |
| 单图 | 当前活动格 | 无 |
| 左右双图 | 两格 | 中间竖条 |
| 上下双图 | 两格 | 中间横条 |
| 四宫格 | 四格 | 行、列分隔条 |

四格使用稳定 ID `pane-1` 至 `pane-4`，单图和双图包含当前活动格，其余按格编号取足。
切换布局时确定可见格；点击已有可见格只改变活动边框，不重排格的位置。
切换布局不重置各格设置；隐藏格保留配置和会话画线，恢复可见时才重新打开原生页面。
隐藏格释放其前端图表连接和临时历史定位请求；放大一格仅临时隐藏其他格，不销毁其他页面。

分隔条支持鼠标拖动与键盘方向键，失焦或在窗口外松开后终止拖动。
每格至少约 340 CSS 像素宽，完整面板至少约 420 CSS 像素高，最终以真实控件测量核定。
普通页面通过纵向滚动容纳双行；放大工作区在可用高度不足时仍允许内部滚动。
容器不足以容纳最低宽度时，图表区自身横向滚动，不改变用户选中的布局或挤压覆盖控件。
保存的是用户设置的比例；窗口临时变小时只约束显示比例，不覆盖已保存偏好。
尺寸变化重新绘制 K 线，不对 canvas 做 CSS 等比例拉伸。

### 3.3 每格操作与联动

每格独立维护品种、来源、周期、年份定位、加载说明、数据时间和错误。
标题中文显示品种、主连或实际交割月份、周期；代码仅作为次要核对信息。
每格保留添加/取消自选、单格放大/还原，右键画图仍只属于图内菜单。
原生周期按钮可继续使用，其选择同步回该格设置。

周期白名单：分时、1分钟、5分钟、15分钟、30分钟、1小时、日线。
首次空白格采用当前活动品种和来源，但使用有明确标签的默认周期；初始化不自动联动已有格。
切换来源保留用户显式选择的周期；尚未选择周期时，主力连续历史默认日线，当前主力默认1分钟。

品种联动默认关闭：

- 行情行、自选列表或格内品种选择只修改活动格。
- 开启后，用户下一次选择品种应用到所有可见格，各格保留各自周期和来源。
- 开启开关本身不立即覆盖其他格；隐藏格不参与联动。
- 联动不包括横向视口、价格范围、十字光标或年份导航。
- 原生订阅列表选择品种也必须走同一条选择规则，不能绕过活动格或联动状态。

单格放大和工作区放大分别保留返回入口；Esc 优先取消未完成绘图/编辑，
没有图内未完成操作时再还原单格或工作区。放大、还原不重建 iframe 或丢失画线。

## 4. 数据与状态边界

### 4.1 后台行情会话

继续只有一个 MarketSession 线程拥有后台只读 TqApi。
正常修改某格不重建整个会话；目录、报价和其他格状态保持。
后台接收可见行情行、自选和可见格的订阅需求，按品种去重。
真实主力取主连 `underlying_symbol`，不能用列表第一项猜测。

后台为可见格准备必要的初始序列与元数据，同一合约/周期可复用准备结果，
但每格拥有独立请求版本、状态与错误；前端实际历史范围以该格真实绘制报告为准。
不同日内周期使用对应 duration，不再假定只有一分钟和日线。
主力映射改变时只更新受影响的实际合约格；主连格和其他品种不应因此重载。

按后台实际订阅过的品种和所需真实合约核算既有容量保护，不把“共用后台”当作免费无限订阅。
新增请求超过当前容量时明确拒绝并保留原布局和原数据，提示减少需求或显式重新连接；
不得通过创建额外账号会话、静默切换服务或不断后台重连绕过限制。
不依赖尚未核实的 SDK 序列取消接口；资源释放和订阅预算需在实施中按锁定版本验证。

### 4.2 各格原生图表

每个可见格使用独立 iframe，复用 SDK 原生静态资源和现有注入适配。
各格原生行情连接和内部 `web_chart` 属于各自原生客户端，须验证不同格同名图表请求互不干扰。
Python 认证、原始 `/url` 认证响应与 WebSocket 对象不经父页消息、业务日志或布局文件传递。

父页与子页仅交换白名单显示信息和命令，消息验证：

- 子窗口身份 `event.source`、准确的本机 origin、格 ID、连接 generation 和格 revision。
- symbol 必须匹配该格已核实合约；周期必须在白名单中。
- 旧连接、已隐藏格、已切换品种和旧版本响应均不能覆盖当前格。
- 图表状态中不携带认证对象、令牌、任意 HTML 或可执行字符串。

已建立的其他格不因某格更改而导航或重置。某格没有权限或数据错误时，只在该格显示原因。
全局连接灯表示后台服务连接；每格单独显示其图表连接、加载和数据状态，不能互相代替。
每格就绪沿用现有实际数据及实际绘制双重检查；不以 iframe load 或全局绿灯认定成功。

### 4.3 共享画线

保留上轮承诺：同一完整合约 symbol 的画线按真实时间和价格共享，主连与实际月份合约隔离。
增加父页会话内画线存储，让相同合约在不同格、不同周期中看到同一份已提交图形。
只同步有限数量的图形 ID、类型和时间/价格锚点，沿用当前交易日边界与实际柱映射。
父页以递增版本接收和发布已提交的编辑，防止同步回环；拖动预览留在本格。
其他格提交更新时，撤回本格同一合约尚未提交的冲突编辑并提示，避免旧编辑覆盖新结果。
撤销只作用于该合约最新的已提交操作，不能把另一个格较旧的快照覆盖到更新版本。

未完成绘图或编辑在切换品种、周期、隐藏格、退出时取消；已提交图形在当前父页会话保留。
新建可见格或重新打开隐藏格时，按合约恢复会话画线；不要求等到定位数据返回才保留锚点。
跨周期历史定位仍可取消、有超时，迟到响应不抢回用户手动视口。
本次不增加画线磁盘持久化，关闭主窗口后不承诺恢复画线。

## 5. 集中的账户区域

隐藏各格内重复的账户区域和程序标题，保留每格必要周期控件及报价说明。
在图表网格下方显示一份可折叠账户区，保留权益、持仓、委托和成交的只读查看能力。
从后台所属账户读取白名单业务快照，在可信父页面呈现；不读取子页认证对象或复制凭证。
各格的画线、滚轮、拖动和单格选择均不改变账户状态。

当前 MarketSession 使用 `TqSim()`；账户区必须明确写“本地模拟账户 · 行情窗口”，
其初始虚拟权益不是真实资金，也不是 `TqKq()` 的服务端余额。
现有研究窗口的快期模拟与实际交易流程保持独立；本次不新增下单入口或启用交易任务。
账户断线时保留末次快照并标明时间与失效状态，不能继续显示为当前有效权益。
成交和委托记录只显示实际返回内容，无成交时显示空状态。

## 6. 布局持久化

使用独立的版本化本机文件 `data/workbench/chart-workspace.json`，原子写入。
不改变已有目录、自选和 Windows 凭据的存储语义。

保存内容：布局、活动格、品种联动开关、用户分隔比例、四格品种/来源/周期和账户区折叠偏好。
不保存认证、行情价格、历史数据、图表地址、连接状态、临时导航或画线。
字段严格白名单；格 ID、周期、来源、比例和合约格式均验证。
旧安装无文件时使用当前单图体验；旧目录/自选文件不需要迁移或重新填写。
文件损坏时明确提示、保留原文件并使用默认布局，不静默覆盖损坏文件。
重启先恢复配置预览，保持未连接，不自动登录、创建账户会话或启动策略。
连接后再用实际目录和映射验证保存品种；失效品种在相应格提示，不能悄悄替换。
保存失败提示“布局未保存”，不影响当前浏览，不声称下次能够恢复。

## 7. 生命周期与异常

- 正常切换格配置只取消该格旧请求；所有格共用的后台连接不因切换而重建。
- 隐藏格终止前端轮询、WebSocket 和临时定位订阅；后台共用序列按已核实的 SDK 能力管理。
- 重新连接增加 generation，所有旧消息失效；按保存配置重新核实各格。
- 关闭仍先确认；取消退出保持布局和连接，确认后停止父页轮询、各格和后台会话，再销毁窗口。
- 单格加载失败允许该格重试；后台认证失败明确全局失败，不换账号或回退服务。
- SDK 资源不匹配时暂停对应原生适配并说明，不能继续显示可能错位的历史或画线。
- 多原生连接若被真实服务拒绝，逐格显示原因，保留已成功的格；
  这是未通过的联网验收项，不能将离线四屏测试当作实际免费权限保证。

## 8. 验收设计

### 8.1 主窗口响应式

在真实 WebView2 中测量和截图：960×680、1280×820、1440×900 和最大化，
覆盖 Windows 100%、125%、150% 缩放下的有效 CSS 尺寸。
两侧导航、登录、欢迎、行情、分页、自选和新闻不得重叠；
表格的水平溢出只能发生在其滚动容器内，页面右侧不能出现意外被挤出去的卡片。
连续改变窗口尺寸、切换页面和放大还原后仍满足边界。

### 8.2 多图与共享状态

- 四格同时展示不同品种，以及同品种日/时/分钟图；分别核对 symbol、duration、时间范围和版本。
- 操作一格的品种、来源、周期、年份、拖动和缩放，不改变其他格；活动格高亮与真实目标一致。
- 联动关闭/开启、隐藏格不参与、各格保留周期/来源，原生订阅列表选择规则一致。
- 分隔拖动、图外松开、失焦、单格放大/还原不残留拖拽；画布尺寸与实际显示一致。
- 每格绘图编辑、跨周期共享、跨格同步、撤销冲突、合约隔离及历史定位取消均有回归。
- 自选各入口同步，账户区只出现一份，明确显示本地模拟账户身份。

### 8.3 可信性、恢复和生命周期

- 同一后台 TqApi 存活期间反复改单格，其他格不重载；订阅预算不可被绕过。
- 不匹配的来源、子窗口、格、generation、revision、symbol、周期和图形载荷均拒绝。
- 模拟部分格拒绝、数据缺失、旧响应迟到、后台断线；局部错误不伪装成全局成功。
- 保存、重启、旧文件缺省、失效品种、损坏文件和写入失败均有确定行为。
- 单图、双图、四图多次切换后，隐藏格无遗留前端连接或临时请求；所有格退出后资源正常释放。
- 保留现有价格轴、年份、历史完整性、幽灵拖拽、凭证隔离、退出确认等检查。
- 产品代码完成后运行 `tools/check.ps1`，再单独记录本机只读联网结果；
  离线成功不代表免费多屏连接权限、开盘实时更新、快期模拟或实盘交易验收成功。

## 9. 实施边界与下一步

本设计包含主页面自适应、多图独立状态、可选联动、共享会话画线、集中只读账户和布局恢复。
不包含自由拼接任意数量面板、脱离主窗口的浮动窗口、同步十字光标、新闻接入、策略编辑、
交易执行或画线永久保存。四格为当前上限，不提前建设通用停靠框架。

预期变更主要落在 `qf/web/`、`qf/market_session.py`、`qf/workbench.py`，
增加小型布局存储与针对性测试；保持线程持有 SDK 对象、前端只收白名单快照的既有边界。
本文件审阅确认后，再编写可分步验证的实施计划，由主代理在当前分支顺序执行。
