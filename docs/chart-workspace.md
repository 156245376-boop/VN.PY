# 行情分屏与窗口布局

工作台使用同一后台行情会话，最多打开四个天勤原生图表；浏览、切换或画线均不产生委托。

## 使用

- “行情图工作区”右上角可选单图、左右双图、上下双图或四宫格。
- 点击图表或标题激活一格，绿色边框表示当前操作对象；在行情行或自选列表选择品种，只改这一格。
- 每格可独立选择中文品种、当前主力合约/主力连续历史、分时或日/时/分钟周期。
  来源切换保留显式选择的周期；未选周期时，当前主力默认一分钟，主连历史默认日线。
- 开启“品种联动”后，下一次选品种同时应用到可见格，各格保留来源和周期；开关本身不覆盖现图。
  视口、十字光标、年份和价格范围不联动；隐藏格不参与。
- 拖动格间分隔条调整比例；分隔条获得焦点后也可用方向键。
  单格“放大 K 线”和整体“放大工作区”都有还原入口；Esc 先取消未完成绘图，再还原视图。
- 同一完整合约的画线在各周期、各分屏共享，仍可编辑、移动、删除和撤销。
  并发编辑按版本核对；冲突时保留最新结果并提示，不用旧快照覆盖。
- 账户区只显示一份，可以折叠。明确标注“本地模拟账户 · 行情窗口”，
  这里的虚拟权益不属于研究窗口的快期模拟账户。

## 缩小窗口

行情表格只在卡片内横向滚动，侧栏容纳不下时移到下方；导航短窗口可自身滚动。
图表区使用整个内容宽度。原生图表需要最小可读空间：每列至少 420 CSS 像素，
每行按控件约 448 像素，含日线定位控件时约 480 像素；更小窗口使用图表区内部滚动。
只约束显示比例，不覆盖保存的分隔比例。

尺寸变化通过父页实测值同步给原生组件，重新绘制而非拉伸 canvas。
WebView2 隐藏窗口不保证及时投递 resize/ResizeObserver，因此保留轮询尺寸补发；
实际绘制的尺寸、合约、周期和数据均匹配后，才结束本格加载。

## 保存与恢复

`data/workbench/chart-workspace.json` 只保存布局、活动格、品种、来源、周期、联动、
分隔比例和账户折叠偏好，不保存行情、认证或画线。
连续修改合并为串行写入；未成功保存会提示，退出前等待已发起的保存并有超时保护。
恢复配置不自动登录或启用策略。失效品种在相应格提示，损坏文件保留原件，不静默覆盖。
画线在当前主窗口会话内保留，包括隐藏格恢复；关闭主窗口后不承诺恢复。

## 数据、连接与退出

顶部连接灯表示后台会话；各格灯读取自己的原生行情连接状态，不能借后台绿灯冒充已连。
各格单独核对实际 K 线与绘制，局部缺数据、权限不足或适配失败不清掉其他格。
后台订阅按实际占用与需求去重计数，超过保护上限明确拒绝，不新增账户或偷偷重连绕过限制。

隐藏格和离开行情页面会释放其浏览器连接；恢复时按配置及会话画线重新打开。
SDK 3.10.2 的原生服务在等待数据时可能阻塞关闭帧，`qf/market_web.py` 对本会话创建的
helper 实例适配接收/发送与 finally 清理；不修改 SDK 文件，构造后立即恢复原工厂。
主窗口退出仍须确认；取消保留会话，确认后保存布局、释放全部格及后台会话，再销毁窗口。

## 实施取舍记录

- 沿用用户确认的当前功能分支与工作目录，未另建工作树；风险是修改直接保留在此工作目录。
- 在现有真实工作台冒烟中增加布局断言，避免另起重复 GUI；风险是一次冒烟覆盖范围较大。
- 后台切换改为缓存复用，旧测试改查单会话与过期结果隔离；风险是缓存占用须持续受订阅上限约束。
- 原生图表按实测最小宽度 420px 保留内部滚动；较窄窗口需横向查看，不能强行挤压原生画布。
- 历史摘要和日线控件预留高度，分隔线按实际边界限位，原比例仍保存；较小窗口可能增加滚动。
- 测试自行确认自己的隐藏退出对话框，并使用文件接收子进程输出；不改变用户退出确认或终止旧软件。
- 本机图表改选经空闲核实的高位端口，避开浏览器禁用端口；仍有端口被外部程序随后占用的极短竞态。
- 行高由初步 520px 调整为实测 448px/480px；可读空间不足时内部滚动，不缩放图片代替重新绘制。
- 每格使用自己的行情连接灯，父页测量与实际绘制尺寸吻合后才显示完成；未吻合时会继续明确等待。
- 对锁定 SDK 的 helper 实例处理正常断开清理，构造后恢复工厂；升级 SDK 需重新验证此兼容点。
- 确认退出前等待布局队列，最多两秒；若写入长期阻塞可能保留上次成功布局，原子文件不被半写覆盖。
- 各周期均检查相邻柱超过 31 天的间隔，保留稀疏缓存窗口区别；极不活跃合约需人工核实数据。
- 截图验收使用可见测试窗口，普通自动测试保持隐藏；DPI 使用 CDP 仿真，尚不覆盖全部实际显示器设置。
- 审查暂不判断实际免费并发条件、全部物理显示器 DPI 及策略/实盘扩展：保留独立验收边界，
  风险是仍需账户、显示器及交易阶段各自验证；本轮没有遗留轻微审查问题。
- 任务记录依据已实际运行的定向及全量检查结果补全，没有仅为补记脚本重复运行已通过的 GUI；
  风险是完成账本由人工抄录，但最终代码另有完整检查与独立审查。
