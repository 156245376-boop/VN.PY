# ADR-0003:策略表达目标持仓,而非委托

状态: 生效
日期: 2026-08-30
承重性: **承重** —— 改动会波及 `strategy/`、`execution/`、`engines/` 的全部适配器,
且已写成的策略需逐个重写

## 背景

同一份策略源码需要跑三种环境:vnpy 单品种回测、多品种组合回测、实盘(R11.8),
且要保留将来更换为自研引擎的可能(R11.9)。

需要决定策略与执行之间的接口形态。自然的候选是让策略直接下单 —— 这也是
`vnpy_ctastrategy` 的 `CtaTemplate` 提供的形态(`buy` / `sell` / `short` / `cover`)。

## 决策

策略只调用 `set_target(symbol, volume)` 设置**目标净持仓**,不直接报单。
挂单与停止单经 `place()` 逃逸接口,并须把自身标记为不可向量化(R11.5)。

## 理由

**核心理由:委托是执行细节,目标持仓是交易意图。让策略表达执行细节,就要求它
知道一整套它不该知道的事。**

如果策略说"用 `CLOSE_TODAY` 买 2 手",它必须同时知道:上期所与能源中心分别记
今昨仓且必须显式标平今、自己当前的今昨仓拆分、当日涨跌停价、平今与平昨的费差
(部分品种平今近乎免费,部分是惩罚性的)。**任何自研引擎都无法复现这一整套行为**
—— 于是"更换引擎不改策略"这条要求当场破产。

如果策略说"我要在 `rb2510` 上净持 −2 手",三种引擎各自都能实现:

- 实盘:与券商真实持仓做差,由 `execution/` 解析开平方向(可复用
  `vnpy/trader/converter.py` 的 `convert_order_request_shfe`)
- vnpy 回测:同样做差,通过 `buy` / `sell` / `short` / `cover` 表达
- 自研引擎:直接物化成目标持仓数组,用 `diff(target) × 价格` 减建模成本算 PnL

**附带收益是解决了 D2 这类状态发散。** 全自动运行下,策略以为开了仓、实际被风控
拒了(R19.6),内部状态就与真实持仓发散,下根 K 线继续重试。R17.12 的"部分成交后
撤单"(要 3 手成交 1 手)是同一类问题。目标持仓形态下这里天然收敛:**目标没变,
执行层下根 Bar 继续尝试** —— 拒单与部分成交不再需要策略自己纠正状态。

## 放弃的方案

- **策略直接继承 `CtaTemplate` 下单。** 最省事,且是框架的默认用法。否决理由有
  两条:一是永久锁死 vnpy(见 ADR-0004);二是 `BacktestingEngine.set_parameters`
  只接收单个 `vt_symbol`(`vnpy_ctastrategy/backtesting.py:114` 实测),多品种组合
  回测(R13)在这条路上做不到。
- **策略产出信号强度(−1 到 +1),由外层翻译成仓位。** 多一层间接,且**信号到仓位
  的映射本身就是策略的一部分** —— 同一个信号在不同资金管理下是完全不同的策略。
  拆出去反而更难理解,且外层需要知道合约乘数与保证金才能翻译,等于把执行细节的
  知识挪了个位置而没有消除。
- **策略直接报单但由 `execution/` 事后改写开平标志。** 看似能兼得,实际上策略仍需
  自行维护"我以为的持仓"以决定报单方向与数量,状态发散问题原样保留。

## 后果

好的方面:

- 同一策略源码可移植于三种引擎,该等价性由 Phase 8 的跨引擎一致性测试(R33.8)
  常驻回归 —— 成交清单与 PnL 须在浮点误差内相等
- 拒单与部分成交造成的状态发散问题在接口层面消失
- 策略的 import 闭包不含交易所规则、费率、券商与委托号,可用 `.importlinter`
  机械验证(R24.13)

坏的方面:

- **挂单与停止单必须走 `place()` 逃逸口,且用了就失去向量化能力**(标
  `vectorizable = False`)。向量引擎遇到该标记须直接报错而非静默错算。
- **`position()` 的语义差一根 K 线**,这是按设计的泄漏:vnpy 回测里下根 Bar 的
  合成成交才更新 `self.pos`,实盘是真实 `on_trade` 异步且可能部分成交。
  **故策略决策必须依据 `target()`,`position()` 只作诊断** —— 这一条须在
  `strategy/README.md` 里加粗,它是回测实盘不一致的头号来源。
- 目标持仓无法表达"以某个价格挂着等"这类意图,该场景只能走逃逸口。

## 相关

- ADR-0004 决定策略不继承框架基类,二者共同构成"策略可移植契约"
- ADR-0005 决定费用计算由回测与实盘共用,是同一目标的另一半
- 需求 R11.4 要求策略以 Target_Position 表达意图且不允许直接指定开平与价格
- 需求 R16.4 要求实盘在每根 Bar 持续收敛目标与实际持仓的差额
- 需求 R33.8 定义跨引擎一致性测试,是本决策真的成立的证明
