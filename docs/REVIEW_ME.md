## 本系统的核心约束(不理解这些,任何建议都会跑偏)

- **行情是约 500ms 的快照,不是逐笔成交。** 单个快照周期内的多笔成交被合并。
  任何依赖逐笔序列的建议(真实订单流、成交方向推断)在这份数据上不成立。
- **策略跑 1 分钟周期。** 语言层与框架层的延迟优化在 60,000ms 预算下不可观测
  (ADR-0002)。"用 C++ 重写"、"减少事件总线跳数"这类建议请先给出 profile 数据。
- **回测与实盘必须调用同一个费用函数**(ADR-0005 / R29.1)。这个同一性是防止
  回测实盘分裂的机制,不是代码复用的顺手之举。
- **免费 1 分钟历史短且有洞,自建录制是主要数据来源。** 故 `raw/` 是唯一不可
  重建的东西,而缺口表是一等输出而非日志行。
- **单人维护。可维护性优先于性能**,除非有 profile 数据。已识别的最大失败风险是
  "一个永远不上线的半成品系统" —— 任何增加复杂度的建议都要对着这条称一下。
- **全自动运行,真实资金。** 故"对账不符时冻结而非自动纠正"(ADR-0009)这类看似
  保守的选择是刻意的:自动纠正会把一次可发现的不一致变成一个静默的错误持仓。

## 缺陷预防机制:为什么这里不欢迎开放式代码审查

[ADR-0001](adr/0001-defect-prevention-and-ai-review.md) 是**承重**决策,请在提出
任何"让 AI 多审查一遍"的建议前读完。

要点:**大语言模型审查大语言模型的产出,其盲点是相关的,不是独立的。** 本项目
会亏钱的缺陷集中在领域规则理解错误 —— 周五夜盘的交易日归属、以收盘价替代结算价、
Bar 时间戳偏移一分钟、换月决策用了当日数据。这些代码都很干净,读起来完全合理,
错误在于**与现实不符**,而非与自身不符。审查者以同样错误的理解读同一段代码,会
审查通过。

由此有两条硬约定:

- **凡可由脚本判定的约束,一律用脚本。** 不以自动化审查替代脚本检查(R34.2)。
- **领域逻辑测试的预期值必须来自系统外部权威资料**(交易所公告、交易日历、券商
  确认的费率表)。模型只写测试输入与结构,预期值标记 `pending_expected` 待填,
  由开发者查阅资料后填入。**标记未填的测试必然失败而非跳过**(R34.7,由
  `tests/conftest.py` 强制)—— 否则测试退化为"模型的理解 == 模型的实现",证明力为零。

如果你要提供帮助,最有价值的形式是**带上外部判据的比对**:给出交易所规则原文或
需求验收标准原文,然后检查实现是否与之一致。开放式提问("看看有没有 bug")在这里
同时承受相关盲点与高噪音两项缺陷,已被否决。

## 我们知道的、还没解决的问题

- **人工核对预期值是整套缺陷预防机制中唯一无法自动化的环节。** "完全跳过"已由
  R34.7 转为可观测;但**"敷衍填入"——照抄实现的当前输出、或向模型索取取值——
  仍然不可观测,且测试会全部通过。** 这是 ADR-0001 记录的主要执行风险,无技术
  手段可缓解。
- **`vnpy.alpha` 是否适用于期货未经实测。** 它是唯一原生多合约 + 原生目标持仓的
  一套,但内置因子集源自 Qlib、示例为股票策略,期货的保证金/平今/合约乘数大概率
  未处理。多品种引擎选型待 Phase 5a 实测后定(ADR-0012 待补)。
- **单机、单券商、单网络的单点故障。** 个人规模下没有聪明的设计解法。诚实的缓解
  是仓位小到全程断网仍可承受,以及一条硬规则:不持有你不愿意在糟糕价格上发现的仓位。
- **Python 3.14 会破掉 vnpy 的依赖**(PySide6 6.8.2.1 声明 `<3.14`)。见 ADR-0014。
- 各模块 README 的「不变式 / 否决过的方案 / 已知局限」三节按 Phase 逐步填写。
  标注为"待 Phase N 填写"的不是遗漏 —— 决策当时的约束与否决理由,事后补写不出来,
  但提前编造更糟。

## 当前进度

Phase 0(骨架)已完成。**Phase 1 的代码已完成,但市场事实尚未核对** —— 这是理解
当前状态最关键的一点:

- `core` 完整;`meta` 的 `models` / `store` / `symbols` / `calendar` 已实现
  (`ReferenceDataStore` 端口、`TradingCalendar` 的唯一交易日出口、合约代码转换)
- 其余 12 个模块仍是存根
- **`tests/meta/test_market_facts.py` 里的市场事实全部标记 `pending_expected`,
  当前必然失败(R34.7)。** 也就是说:`to_trading_day` 的换日逻辑已被测试,但它
  依据的交易日历与时段定义**还没有经过任何外部资料核对**。算法自洽 != 与现实相符,
  这正是 ADR-0001 要防的那类缺陷。

因此 `pytest` 单独运行**必然非零退出**,这是设计如此。门禁请用 `tools/check.ps1`
(两段式:已核对用例必须全过,待填用例必须不全过)。

各阶段的落地时机见 `CLAUDE.md` 的模块清单与 `IMPLEMENTATION_PLAN.md` 的分阶段实施。
