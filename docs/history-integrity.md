# 历史图表自审与修正（2026-10-17）

本轮针对“菜油从 2026 年向前只看到 2016 年”排查了后台序列、原生前端缓存和实际绘制窗口。
环境固定为 Python 3.13.11 / TqSdk 3.10.2；仅使用禁止下单的只读行情会话。

## 实测范围

- 当前账户目录 88 个国内期货品种，各请求最新至多 3000 根主连日线，检查逐年数量、
  时间重复/倒序、有效柱之间的内部无效行及较长日期间隔。
- 菜油 `KQ.m@CZCE.OI` 返回 2618 根：2016—2021 每年 243 或 244 根，2022—2024 每年
  242 根，2025 年 243 根，2026 年 189 根。2017—2025 年均存在。
- 88 份序列本次均有有效日线，没有重复/倒序时间或内部无效行；强麦有一处 25 个自然日间隔
  （2022-09-15 至 2022-10-10），仅列为需核实观察，不据此推断缺失或权限问题。
  晚稻本次末日为 2026-01-16，不能视为当前行情；其他品种的起止日期也按实际返回显示。
- [各品种与各年计数](evidence/history-coverage-2026-10-17.csv)仅保留覆盖摘要，无价格、凭证或认证响应。
  本次返回范围不等于上市以来全部历史，也不是逐个交易日和成交源的完整性证明。
- 使用新增后台校验器再次只读联网检查：88 份序列均初始化成功，通过本轮结构、编号、时间和
  超过 31 天间隔检查；不因此将 31 天以内的交易日缺失或无交易情况判为已完整验证。
- 修正后在真实独立窗口中逐年定位菜油 2016—2026 全部 11 个年份，核对实际绘制范围，
  中间九年均可打开。日线横轴显示完整年份。

原先的具体“跳年”操作本轮未稳定复现，不能将某一个已查明缺陷断言为其唯一原因。
原代码确有以下漏洞，均已补充回归。

## 修正与保护

1. SDK 原生日线横轴的周期判断错误，不显示年份；在应用层适配为北京时间完整日期。
2. 原生历史请求遗漏 `left_kline_id=0`，可能重新请求最新窗口；保留显式零值，
   同时修正原生用于退订的 `view_width=0`。不改 SDK 安装文件。
3. 原生周期控件会丢失日线选中状态；按实际绘图周期同步。
4. 原来 DOM 加载事件就会隐藏进度。现在必须核对当前符号、周期、服务响应、实际绘制数据和可视范围。
   空图不能显示就绪，切换后的旧消息不能覆盖现图。
5. 后台不再丢弃 K 线序列。合法的前导占位与内部异常分开检查；空数据、非有限价格、
   编号空洞、重复/倒序时间、日线超过 31 个自然日的可疑间隔均明确阻止就绪。
   分钟线不按固定周期差误报午休、周末或节假日；31 天筛查不是交易日历校验。
6. 前端独立拉取图形数据，因此还检查实际绘制源的有效 OHLC、编号、时间和已请求窗口内部空洞。
   未请求的缓存区间不冒充已验证历史；异常时暂停显示，不插值或补价。
7. 图表显示已加载日期、根数及当前可见日期；日线可按实际收到的年份直接定位、回到最新。
   最后一根日线可能尚未完成，夜盘日线可能归入下一交易日。
8. 修正标签脚本遇到晚到标题节点时中止观察，以及停止期间旧图表地址重新发布的竞态。
   内部切换其他品种统一交回工作台选择，避免标题与图形不一致。
9. 当前请求范围与回应一一核对，实际绘制绑定数据版本；分包确认不能使未重画的数据显示就绪。
   帧身份同时使用地址与会话版本，地址复用也会重新握手。
   服务端状态按增量合并，显式 `null` 删除字段；已完成的同参请求可复用确认，
   不要求服务器重复发送没有变化的状态。真实服务的这两个行为均已加入离线回归。
10. 按用户补充的“主力连续历史、拖动日线”路径，额外复现了原生拖拽状态残留：
    按下后在 100ms 内移出图表并在外松开，延迟任务仍启动拖拽；回到图上仅悬停移动 120px，
    就继续平移约 15 根日线。适配层现在清除未开始的延迟任务，并通过原生释放处理结束已开始的拖拽，
    保留原生结束通知与动态监听清理。窗口失焦、页面隐藏或无左键按下的移动均补充收束；
    仅真正离开图表根节点才按离开处理，跨主图、坐标轴和成交量区域不提前终止。

SDK 原生画图还有一项已明确的限制：仅有 `id=0` 一根有效柱时会提前返回，无法绘图。
不篡改柱编号来绕过它；此情形明确显示单柱限制，不再永远停留在加载中。当前 88 个主连均非此情形。

原生适配只针对锁定的 SDK 静态资源，核对文件指纹名称和运行时形状；不匹配时明确暂停显示。
升级 SDK 时须复核适配与真实窗口回归，不通过改写安装目录或绕过权限来修数据。

## 验证

离线回归覆盖空图、前导占位、内部空洞、2016/2026 两端存在但中间断档、时间重复/倒序、
合法休市间隔、旧请求迟到、停止竞态、真实原生脚本零值请求、周期状态与全部年份导航。
工作台冒烟使用本机合成 K 线并阻断外部 WebSocket；不把出现工具栏视为有效 K 线。
全部检查仍以 `tools/check.ps1` 为入口；账户联网验收与离线检查分别记录。

最终检查：`tools/check.ps1` 全部通过，161 项 pytest 测试及 Ruff 通过，其中原生脚本覆盖 24 组场景；
SDK 自带 demo/web 共 135 个文件的 RECORD 校验通过，安装资源保持原样。
本机最新只读窗口确认菜油分钟图与主连日线均正常结束加载，2016—2026 全部年份导航通过，未产生委托。

用户补充拖动路径后，再以 WebView2 CDP 发送真实鼠标事件验收主连日线：
连续 38 次拖动到最早边界，经过 2016—2026 全部年份，单次最大移动 74 根，符合当次约 586px、
每根 8px 的位移；最终可见 2016-01-05 至 2016-06-23，图表保持就绪，没有异常跳年。
原代码的快速移出/图外释放漏洞单独复现；修正后同样操作下拖拽已结束，随后仅悬停移动 120px，
视窗移动为 0。正常拖动和释放边界两项均使用浏览器可信鼠标事件，未产生委托。
本次不能据此认定拖拽残留就是用户最初一次跳年的唯一原因。

2026-10-18 分屏联网核对补充：菜油实际合约小时缓存也出现了 2016 与 2026 年数据。
所有受支持周期现均检查相邻真实柱超过 31 天的可疑间隔，明确提示并暂停显示；
不再只对日线检查，也不推断未请求的稀疏缓存窗口之间缺失。正常夜间、周末与长假不因此误报。
这项保护不补造历史，也不证明同代码跨十年数据属于同一交割月份；具体服务数据仍须核实。
