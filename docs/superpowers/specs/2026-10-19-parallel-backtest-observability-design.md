# 多实验并行回测、账户与止损可视化设计

状态：用户已审阅并确认本文；实施计划已编写，尚未开始产品实现。

## 用户目的与验收体验

用户要用双均线等简单策略验证个人交易系统，能看到每笔交易的风险依据、账户变化，并同时研究不同品种和周期。成功不以“回测能跑完”为唯一标准，还要求可观察、可核对、可比较，运行期间可以继续准备另一项实验。

用户明确选择多个实验同时计算并切换查看，不能以串行排队代替并行。未来目标是多品种共享资金的组合回测、组合模拟和实盘；本轮建立独立实验管理能力，后续共享资金执行与组合风控单独设计验证。

用户实际反馈和只读证据见 `docs/superpowers/reports/2026-10-19-research-display-and-performance-diagnosis.md`：161条成交、80笔完整交易，账户栏未收到完整数据；首笔开仓3301、止损3284有记录但图上不可核对；取消观看后仍生成快照、重复处理旧柱；现有研究入口只有一个工作线程并锁定表单。

## 采用方案与边界

采用小型回测任务管理器，加上独立子进程和现有实验/结果存储，不创建通用交易框架。

| 方案 | 适用性与取舍 |
| --- | --- |
| 维持单任务、其他排队 | 改动较少，不能满足用户已确认的同时计算 |
| 多线程共用研究进程 | 易与SDK任务、全局日志和界面争用，不能可靠利用多个CPU核隔离独立回测 |
| 独立进程运行各项回测 | 采用；每项拥有自己的SDK、虚拟资金和记录，父进程管理生命周期及有限展示副本 |

范围包括现有版本2固定合约和版本3历史主力连续回测；版本1继续只读复制升级。当前TqSdk 3.10.2、Python 3.13.11和既有依赖锁不变。

快期模拟继续使用现有单账户串行控制和账户锁；本轮不允许通过回测任务入口启动模拟或实盘。并行独立实验的收益不得合计为一份资金的组合收益。

官方多进程参考：<https://doc.shinnytech.com/tqsdk/latest/advanced/backtest.html>。官方提示同时回测不要超过10项；本应用首版默认2项并行，可在设置中选择1—4项，实际认证、数据和服务限流仍以账号返回为准。达到本机上限的新增任务明确显示“等待空闲”，已有两个任务必须真实同时运行。

## 工作台操作

研究页分成实验编辑区、回测任务列表和当前选中任务的观察区，继续使用现有工作台窗口。

1. “新建实验”“复制实验”和品种/周期/日期编辑在其他回测运行时仍可使用。
2. 点“启动回测”保存不可变实验修订，并创建新的任务卡；卡片显示品种、周期、参数摘要、预热/回测阶段、历史日期、进度、耗时和成交计数。
3. 点击任务卡仅切换观察对象，不重新连接账户、重启回测或改写表单草稿。选中观察的任务与正在编辑的实验分别明确标识。
4. “停止本任务”只作用于明确选中的任务；停止按钮的文字包含任务名称。其他任务不受影响。后台任务不因隐藏页面或切换品种而停止。
5. 每项可以切换“快速计算”和“观看过程”。首版同时只观看一个任务，其余任务继续快跑；切换观看会停止旧任务的重型图形快照订阅。
6. 任务完成后可以独立复盘、复制参数或加入比较，继续复用已有结果比较入口。比较依据是实际运行修订，不使用编辑区尚未保存的参数。
7. 附加双倍费用回放仍是独立任务，标记为基准的费用压力子实验，不覆盖基准结果；提交前说明将新增一项任务。

容量和等待状态不使用“运行中”伪装；任务失败显示其日期、合约与白名单原因，不覆盖其他任务状态。预热继续显示独立进度和不下单说明，保存并核对通过后才显示回测完成100%。

## 进程、状态与生命周期

### 父进程

任务管理器只处理创建、并发容量、控制命令、有限快照和退出，不拥有SDK对象或活动SQLite连接。

每项使用随机`job_id`；创建时冻结实验id/修订、配置、费用倍率和代码来源。启动后由子进程创建唯一`run_id`并回报。任务存根放在`data/workbench/backtest-jobs/`，只含脱敏身份、状态与结果关联，不含凭证和原始异常。

状态为等待、启动、预热、回测、停止中、保存中，以及完成、已停止、失败、冻结、异常中断。任务控制不能依赖“当前全局任务”；每次必须核对明确`job_id`及其所属本机会话。

默认2个运行槽位；调整上限向下时不杀死已有任务，仅阻止启动更多。第二个工作台实例不能接管或重复启动仍由原实例持有的任务池；使用项目内管理器锁给出明确说明。

### 子进程

Windows采用`multiprocessing`的`spawn`方式，使用项目隔离解释器；工作函数可导入但没有创建窗口的副作用。桌面入口遵守主模块保护和`freeze_support()`，后台不弹出额外控制台。

每项在自己的进程创建一个TqApi、一个TqBacktest、一个TqSim，沿用用户日期、精度、主力换月、信号、风险和费用规则。每个结果目录只有所属子进程一个写入者。禁止在进程间传送SDK对象、日志认证对象或SQLite连接。

凭证由现有本机登录入口取得，通过父子私有内存通道一次传入；不放在命令行、任务存根、实验文件、输出或错误信息中。任务结束释放内存引用；父进程不为展示读取或输出密码。

控制通道与大图形快照分开：停止命令不排在图形消息之后。轻量状态和图形快照均有容量限制，拥塞时覆盖旧的展示帧；成交、风险和最终结果不依赖可能被丢弃的图形帧，仍在子进程事务落盘。关键终态使用可靠消息及进程退出结果交叉核对。

公开消息带`job_id`、`run_id`、本次进程代号及递增序号；父进程和页面均拒绝过时或不匹配消息。纳秒时间按字符串传至JavaScript，继续用BigInt映射。

### 停止、崩溃与退出

单任务停止沿用已有回测清理规则：停止新增目标，取消执行任务并等实际确认；移仓期间清理未决旧/新仓意图，不将取消视作平仓。回测期末正常持仓按SDK权益计入，不伪造平仓。

工作台退出沿用确认弹窗，显示运行及等待任务数。确认后取消未启动任务，向所有已启动任务发停止信号，继续收取保存/确认结果；界面显示退出清理状态，不阻塞消息泵。

等待上限沿用任务执行超时加5秒清理余量。超时只允许结束本应用本次会话拥有且仍可验证身份的子进程，禁止按python进程名批量结束。相应任务记为异常中断/状态未确认，不能标记正常停止或100%完成；已提交的证据保留。

父进程异常退出时，子进程检测私有控制通道断开后进入停止清理，避免无人管理地继续运行。重开软件不会自动重跑或恢复旧意图；核对任务存根、进程归属和已有结果，显示中断或实际已保存终态。损坏或未完成结果不强行补写成功标记。

## 账户数据显示与记录

### 唯一数据来源

研究观察区的账户栏明确标为“本次回测账户”，来源是选中任务自己的SDK账户。行情浏览的本地TqSim和快期TqKq继续使用各自标签与来源，不混入研究账户。

复用`account-view.js`的有限账户展示，增加明确的研究场景标题、历史时间和状态。研究图下原生空账户区被该账户区替换，保留一份可用的账户/持仓/委托/成交视图；行情图布局不随此改动变化。

白名单至少包含权益`balance`、浮动盈亏`float_profit`、保证金`margin`、可用资金`available`、SDK日内手续费`commission`、累计手续费、移仓手续费、实际成交条数、完整逻辑交易数、未结束持仓，以及持仓、委托、实际成交的必要业务字段。无效或未记录字段显示“未记录/待核实”，不能显示为0；有效的0照常显示。

账户时间为当前处理到的历史时刻。停止后显示“末次回测快照”，不得继续表现为活动账户。新任务启动不得短暂显示上一个任务的余额或持仓。

### 费用与计数口径

界面分别显示日内手续费、回测累计手续费、移仓手续费；移仓费用标注为累计费用的一部分。累计费用按已保存的逐实际成交费用去重汇总，不用末日SDK字段代替全程值。正常完成时与SDK最终全程统计核对，差异超过0.01元需明确列出来源和不一致，结果不能标为成本核对通过。

成交条数、已结束完整逻辑交易数和未结束持仓分别显示。例如本次161条成交是80笔完整交易加上未结束持仓，不能写成161次完整交易。

### 历史采样与兼容

新增可选版本的账户证据模型：`account_schema_version=1`，`research_accounts(seq,time_ns,trigger,data)`，按时间及序号索引。新回测按完成柱、实际成交、保护档位/合约段变化和终态采样；同一纳秒的多个节点用序号区分。轻量运行快照可按实际等待时间节流发布，历史采样精度在页面明确标识。

持久化数据仅含白名单，纳入结果完整性清单和CSV导出。新读器仅在版本标记存在时要求新表；旧结果按旧完整性算法校验，不能因为缺新表而被全部判坏，也不能把删掉新表的新结果当成旧结果。

复盘按光标/所选历史时间读取最近且不晚于该时刻的账户证据，给出采样时间；窗口首次打开默认末次已保存状态。仅展示最新状态时也不能用未来状态覆盖过去的光标时刻。

旧结果保持只读：已有equity、成交费用、风险事件继续可用，缺失的历史浮盈、保证金、可用资金明确未记录。不能用今天的数据、期末余额或估算保证金冒充当时快照。当前161条成交的结果应能恢复已有权益、累计费用和止损依据，不要求用户重跑才能查看这些已有证据。

## 每笔交易的止损与保护轨迹

图上可选择显示初始止损、当前保护轨迹及拐点依据，默认开启初始止损和当前保护，选中交易时高亮对应拐点。点击成交箭头或交易列表定位该笔交易，并在侧边显示：

- 开仓原因、交叉时快慢均线数值及信号完成时间；
- 止损依据的波峰/波谷所在柱、确认时间、左右确认根数；
- 实际开仓均价、初始止损价、实际距离、手数、初始R和风险预算；
- 达到1R、2R等节点时，保护从何价移到何价，实际触发的退出原因；
- 所属实际合约、换月进出和当时生效的保护价。

预算1000元不代表实际初始R一定等于1000；按整手取整后可以是850元。第一档偏移1跳仍明确不保证覆盖实际手续费。

### 绘制规则

保护段以逻辑交易、实际合约段、持仓数量及生效时间为边界，使用同一风险记录推导；展示层不另算一套止损策略。

1. 初始计划价与成交后实际保护分开。实际持仓保护从首次成交开始，到退出/移仓平旧结束；不在没有持仓时延长。
2. 当前有效末段延伸到已处理历史时刻；不要求必须存在下一条事件才显示。跨窗口查询至少带入左边界前最后有效状态。
3. 同柱内多次变化按真实纳秒次序保留，价格未变可合并绘制；极短段提供可点击节点，不以零长度线掩盖。部分成交引起的数量/保护变化保留。
4. 连续信号图按当时合约偏移投影，详情同时显示实际保护价与信号坐标；调整价为0或负数仍有效，禁止用数值真值判断丢弃。
5. 换月平旧和开新之间断开线，接新后标为“换月接续保护”。原合约的初始真实止损不直接画成新合约真实止损；原初始R继续保留。
6. 图层和查询均有界；运行图保持最近500根，复盘按窗口读取。完整原始风险证据保留，不能通过静默丢弃事件改变保护轨迹。

旧版风险记录和版本3金额风险分别经过适配进入相同保护段契约，不把两种状态格式混读。绘图开关、颜色和选中交易不影响计算、委托或记录。

## 性能优化及可验证指标

先减少单任务无效工作，再验证多任务吞吐；当前不加入GPU计算路径，不以CPU占用越高作为成功标准。

快跑模式只发布轻量状态和账户摘要；未订阅的任务不构造K线/均线/风险图形快照。观看订阅由可靠控制消息传入所属进程，只对选中任务启用，节流沿用约0.2秒；终态无需观看也可靠保存。快跑、观看及切换必须得到相同交易结果。

快跑完成后点查看图形，直接打开该任务已保存结果的离线复盘，不为补一张运行图重新启动SDK或回测。未产生K线的失败任务显示结束原因，不能留下空图持续加载。

完成柱处理以已确认的序列进度为依据，避免每次把整个窗口重新转换和追加；形成柱、SDK CLOSE证据、完成柱变更检查、换月共同参考柱仍须保留。不能为了减少计算引入未来数据，或把过时中间交叉补成当前委托。

展示计算和非关键行情/账户采样允许按既定边界合并；成交、订单用途、风险/目标和移仓确认继续按现有事务强度保存，不能通过关闭同步持久化、跳过数据覆盖检查或丢关键记录换速度。

基准按固定输入分别测量：SDK等待、数据处理、信号/风控、数据库保存、图形快照和界面耗时；输出实际每秒处理柱数、完成总时长及各任务吞吐。合成SDK本身耗时单列，不当作真实SDK瓶颈。

性能门槛：未观看的任务图形快照构造次数为0（显式请求终态图除外）；1000次重复更新不会触发约17万次旧柱追加；优化前后同一冻结基准的信号、目标、实际成交、费用、资金和终态一致。运行时间以多次测量的中位数报告，不预先承诺倍数；两任务并行必须有不同PID和重叠运行时间，不用两项顺序完成冒充并发。

已记录的反手衔接、最小开仓支持及批量补柱语义问题不以“性能优化”名义静默改变。实施前先做针对性复现；若会影响本轮正确性验收，单列缺陷与修复基准，再进行性能等价比较，不能拿已知错误输出充当正确基准。

## 组件边界与现有接点

| 单元 | 职责和现有接点 |
| --- | --- |
| 回测任务管理 | 新增小型`research_jobs.py`，管理任务身份、并发、控制与终态；由仅回测的`research_jobs_bridge.py`接入WorkbenchBridge，不取代模拟账户锁 |
| 独立工作入口 | 新增`research_worker.py`，复用execute_research，隔离SDK、凭证内存和结果写入 |
| 账户证据 | 专用有限快照/采样适配，接research_runtime、continuous_runtime和现有账本/读器；复用account-view展示 |
| 保护轨迹 | 专用保护段适配，接已保存风险、成交和合约偏移；native-replay图层消费，不接下单API |
| 页面任务列表 | 独立轻量模块接research.js，编辑草稿与观察任务分开；复用ExperimentStore、结果比较和复盘 |
| 图形展示 | LiveResearchView按明确任务绑定只读快照；一个任务的快照不得跨入另一图；离线ReplayView仍只读结果 |

新增桥接接口限定为创建/列出/查询/停止回测任务、设置观看、打开指定任务运行图和调整容量。参数使用受校验的实验修订及任务编号，不向页面开放进程、文件路径、命令或任意Python入口。

现有模拟入口和原CLI兼容保留；老的无job参数研究调用只保留明确的单任务兼容适配，存在多个回测时不猜测停止目标。无效/不存在的任务编号必须失败，不回退到当前任务。

## 验收清单

1. 两项不同品种/周期的离线任务真实并行、资金/成交/结果隔离；同一实验重复运行也具有不同身份。
2. A运行时新建/复制B、启动B、切换A/B、停止B，A持续推进；切换不串图、不改草稿、不重启。
3. 四个并发设置边界、容量等待、取消未启动任务、降低容量和单项失败不影响其他项。
4. 账户五项数值、有效0、缺失值、日内/累计费用、持仓和成交计数正确；跨交易日、停止、期末持仓及新旧结果兼容。
5. 初始止损、1R/2R保护、部分成交、同柱多节点、窗口边界、末段、零/负信号价、换月断段均可见且价格可核对。
6. 用已有161条成交结果只读复盘，恢复可用的止损/权益/费用，明确旧缺失字段；原结果内容与完整性不变。
7. 快跑/观看/切换及串行/并行得到各自相同的冻结基准结果；测量并报告性能，拒绝以高硬件占用代替正确性。
8. 身份/序号过期、认证失败、权限不足、拒单、断线、子进程崩溃和控制通道中断均有明确终态；无凭证泄露。

## 后续扩展与本轮不做

今后的路线是：独立并行回测 → 多品种共享资金组合回测 → 组合模拟 → 明确授权后的实盘。实验身份、版本、风险证据和结果接口可以复用；共享账户资金分配、组合保证金/回撤限制、同合约多策略意图协调和实盘执行权威需要另外实现，不能把独立TqSim任务池直接用于同一实盘账户。

本轮不增加组合资金账户、GPU引擎、自研撮合/数据仓库、实盘入口，也不改变既有3R终点为条件持仓。新增设计完成后，需用户审阅本文，再编写并审阅实施计划和选择执行方式。
