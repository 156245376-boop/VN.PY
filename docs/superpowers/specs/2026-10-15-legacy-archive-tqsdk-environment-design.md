## 封存形式的选择

| 方式 | 保全与上下文影响 | 结论 |
| --- | --- | --- |
| 版本化 ZIP、内置校验清单、外部短索引 | 保留当前文件字节，默认文本搜索不会展开包内旧规则 | 采用 |
| 把原目录移到 legacy/ | 容易查看，但旧指令、源码、测试仍可被扫描或误导入 | 不作为默认封存方式 |
| 仅靠 Git 历史或旧分支 | 当前未提交与未跟踪内容需另行保存，恢复入口也不直观 | 保留 Git 历史，不能单独替代封存包 |

## 封存包的内容与恢复

采用 archive/legacy-vnpy-2026-10-15.zip；同名包已存在时禁止覆盖，应核实后另取版本名。
archive/README.md 只记录用途、包哈希、
源文件数量、状态限制及恢复步骤，不复制旧架构正文。封存包纳入版本控制。

包内 project/ 保存冻结清单中每个文件的相对路径与原始字节，保留点文件、空文件。
包括旧 src/、tests/、tools/、docs/、.kiro/、conf/，以及旧 AGENTS.md、CLAUDE.md、
README.md、pyproject.toml、uv.lock、.python-version、.importlinter、.gitignore
和 .vscode/settings.json。当前方案与后续新路线文件不混入旧成果清单。

包内 metadata/ 保存逐文件路径、长度与 SHA256 清单、原 HEAD、Git 工作区状态、
相对 HEAD 的二进制补丁及排除说明。它是源码工作树快照，不声称包含完整 Git 历史；
现有 .git/ 保留在原位置。

不打包 .git/、任何虚拟环境、缓存、真实凭证、运行数据或结果。
打包清单独立检查凭证路径，不能只相信 Git 忽略规则。若执行时发现运行数据、
符号链接、未知忽略文件或清单发生变化，先分类保留，不套用源码清理规则。

必须先完成 ZIP 成员集合、大小、逐文件 SHA256 和包整体 SHA256 校验，再解压到
活动树以外的临时目录复验。验证通过后，才按冻结清单逐文件移出旧活动内容；
不使用针对仓库根的递归清空。每个源文件移出前再次核对长度与 SHA256；
若冻结后发生新增或修改即中止迁移，保留新变化，不能把它们当作已封存内容移出。
所有写入、移出路径先解析并确认位于各自指定目录内。
验证失败时，旧文件保持原位；迁移中断时可凭包与清单恢复，不能宣称切换完成。

恢复时先核对包哈希，安全解压到活动树外，再核对清单；查看或取回单个功能。
不把整个旧目录直接覆盖回新主线，也不在活动目录解压旧 AGENTS.md。
恢复得到的旧系统仍是未完成版本，市场事实待核对的状态同时保留。

新根 pyproject.toml 与 uv.lock 只描述新路线，不继承旧 vn.py、vnpy_ctp 等插件
或自建仓库依赖；天勤自身依赖的 tqsdk-ctpse 等包正常进入新锁文件。
沿用 uv 管理并锁定传递依赖；本阶段按环境项目管理，不生成空策略或旧模块的替代骨架。
项目脚本通过 UV_PROJECT_ENVIRONMENT 显式指定 .venv-tqsdk 的绝对路径，
并在结束时恢复原环境变量。
安装、检查均使用该环境的实际解释器，不能依赖终端中遗留的激活状态、裸 pip 或 qf。

裸 uv sync 仍会默认使用根 .venv，不能作为新项目文档中的执行入口。
忽略规则覆盖两个环境与运行期数据，封存包本身不被忽略。

此阶段不保存密码模板中的真实值，不创建 TqApi 会话，不运行行情、模拟单或实盘单。
