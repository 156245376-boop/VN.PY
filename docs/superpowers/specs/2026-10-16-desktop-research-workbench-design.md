# 桌面策略研究工作台设计稿

日期：2026-10-16（Asia/Shanghai）。状态：产品目标已确认，设计细节待用户审阅；不是实施完成记录。

## 1. 目的与范围

面向个人国内期货分钟策略研究，形成可日常使用的独立桌面软件：
中文浏览市场与主力行情 → 选择策略和参数 → 回测 → 解释与比较 → 快期模拟 → 复盘。
首页以选择策略、品种及回测验证为主；行情浏览和模拟监控均有独立入口。

用户已确认：策略主要通过与 Codex 文字沟通实现，同时保留经典模板；
参数支持新增、移除、修改；新闻事件要有分级，并可配置事件前后暂停开仓等自动规则。

“市场品种”按原项目目标指国内期货，列出 SDK 可查询的品种与合约，分别标识可读行情、
历史数据和交易权限。股票、外盘和期权交易不扩入首版。列表可浏览不表示账户均可交易。

现有固定螺纹样例保留为回归验收基准；未来产品支持受控选择，不再把固定样例作为唯一入口。
不恢复封存架构，不自建行情服务、撮合引擎或全市场永久数据仓库。
实盘接入仍在研究和模拟验证后的独立阶段，当前设计不增加实盘下单入口。

## 2. 桌面形式与页面组织

采用一个独立主窗口：桌面快捷方式 → 窗口登录 → 工作台，日常无需打开外部浏览器或终端。
优先使用成熟 WebView 桌面容器承载本机页面，Windows 使用 Chromium/WebView2；
正式实现先验证当前 Python 环境、原生天勤页面和窗口生命周期的兼容性，失败时明确报告。
不回退到旧 IE 引擎，不修改 SDK 打包前端。现有 Tk 入口在新入口验收前保留。

复用天勤 SDK 的数据、账户、回测与原生实时图形。中文操作、实验档案和持久复盘属于项目界面。
原生实时页可作为内嵌视图；历史复盘以保存的 K 线和成交为输入，采用成熟 K 线组件呈现。
桌面窗口内部使用网页技术，不改变独立软件的使用方式；行情连接仍需在线服务。

| 页面 | 主要内容 |
| --- | --- |
| 研究首页 | 新建实验、最近实验、待比较结果、数据就绪提示和模拟任务摘要 |
| 行情与品种 | 中文搜索、自选、实时主力报价、合约详情和主连映射 |
| 策略研究 | 策略说明、版本、参数编辑、新建或复制实验 |
| 回测与比较 | 回测任务、结果指标、K 线成交复盘、实验列表和差异比较 |
| 模拟运行 | 观察/允许模拟委托、任务版本、行情时间、信号、持仓、委托和成交 |
| 新闻与事件 | 新闻快讯、财经日历、事件分级、品种关联和自动规则状态 |
| 设置与资源 | 数据权限、费用来源、本机记录、官方示例、组件和技能说明 |

窗口常驻标明：研究/回测/快期模拟模式、数据新鲜度、任务状态；
行情更新时间与本机程序心跳分开。切换页面或看另一个品种不改变正在运行任务的执行合约。

## 3. 中文品种、主力与数据范围

- 显示中文名称与代码、交易所；支持中文/代码搜索、自选和按交易所筛选。
- 品种行显示当前主力真实合约、最新价、涨跌、成交量/持仓量及数据时间；不可用字段明确标记。
- 主连用于研究观察，实际交易合约独立显示；映射来自 SDK，不能用列表第一项猜主力。
- 主力报价随行情更新；主力映射改变时展示记录和提示。运行任务继续遵守暂停核实规则，
  不因浏览器切换或主力变化自动换月。
- 市场目录与实时订阅分开：优先订阅可见行、自选与运行任务，分批刷新，避免全市场无界订阅。
- 休市、行情陈旧、未连接与权限不足分别显示；不能把休市没有新 Tick 误报成程序停止。
- 历史样本核实当时合约覆盖、交易日及夜盘，不以今天是否到期排除历史合约。

## 4. 策略与可编辑参数

工作方式：用户描述交易规则 → Codex 实现与验证 → 登记为有说明的策略版本 → 界面调参与实验。
首版不内置另一套 AI 聊天、任意 Python 执行器或通用可视化策略编程工具。

每个策略包含名称、说明、版本/代码指纹、适用品种/周期、预热要求、信号与执行规则、参数定义。
首批模板为现有均线过滤样例、双均线与通道突破；各自先核对信号时点及执行语义，再登记可运行。
经典模板是研究起点，界面区分演示模板、研究草稿、已验收实现与模拟中版本。

参数编辑遵守：

- 修改已有参数值时校验类型、范围、单位、必需项及参数之间的关系。
- 新增/删除参数形成策略定义草稿；只有实现声明消费了该参数，才可发布为新的可运行版本。
  无对应逻辑的自定义字段明确标为草稿，不能静默忽略后声称已经生效。
- 可选参数组可以启用或停用，停用后的逻辑需明确；被策略引用的必需参数不能直接删除。
- 运行中的策略版本和参数固定，编辑生成下一版本/新实验，不热改正在执行的任务。
- 每个可交易信号输出结构化原因和当时输入；记录未触发、预热不足、数据无效及规则拦截原因。

## 5. 实验、回测和比较

新建实验选择策略版本、参数、品种/历史合约、周期、起止时间、本地初始资金及成本假设。
启动前检查数据覆盖与权限；缺数据、认证失败和不可交易样本明确失败，不替换为其他样本。
SDK 模拟费用/保证金与银河实际费用分别标明来源；保留独立双费回放及撮合局限说明。

实验有用户可读名称与唯一 ID，状态区分草稿、排队、运行、完成、失败、中止；
无成交是结果，不能与缺数据或运行失败混为一类。初期任务串行，避免无界并发和账户冲突。
记录固定版本、脱敏配置、数据范围、成本来源、信号、目标、委托状态、成交和权益。

结果页呈现净收益、最大回撤、权益/回撤曲线、费用、成交次数和未平仓结果。
复制实验继承设置并生成新 ID，记录源实验；修改后保留差异，不覆盖旧结果。
比较页展示参数、时间/品种/资金/费用差异；不同口径明确标记，支持选择基准和候选实验。
后续扩展少量参数批量比较、样本外验证和多品种共享资金组合，不能把独立单品种结果相加当组合。

## 6. K 线成交位置与交易原因

本机天勤原生前端已有成交记录、K 线成交箭头和按成交时间定位能力，优先复用。
原生箭头按柱高低位置绘制，并可能合并同柱同方向成交；实际成交价以逐笔成交记录为准。
多合约定位需同时切换合约和时间，不能只跳时间后仍显示另一个合约。

项目复盘补齐三个关联：信号/决策 → 目标与委托 → 实际成交。
决策记录采用稳定 ID，包含策略版本、完成柱时间、输入与原因；执行及成交记录明确关联决策。
部分成交、追单、撤单、拒单均保留，信号标记与实际成交标记分开；不能按最近一分钟猜成交原因。

保存本次研究必要的 OHLC、时间/交易日、信号与成交快照，使用户关闭软件后能从实验档案重开复盘。
记录窗口覆盖与缺口；缺失时不填造 K 线。只保存实验所需数据，保存范围遵循数据服务许可。
现有 SDK 图形服务随 API 会话关闭，不把它当持久回测档案接口。

验收场景：选一笔成交 → 图表切到正确合约/时间 → 展示真实成交价量 → 查看对应信号输入和规则原因；
重启软件后对同一实验仍能完成该流程。

## 7. 快期模拟任务与运行保护

从选定实验创建模拟任务，继承策略版本与参数，重新核实当前真实主力合约与账户状态。
模拟使用 TqKq 主账户和服务端真实模拟余额；本地回测资金不覆写模拟余额。
首版保持一个主账户、一个受控执行任务串行；多品种可研究，不因此开放多策略抢占同一账户。

运行页显示：连接/数据时间、当前策略与参数、最新决策、目标仓位、实际持仓、未决委托、
逐笔成交、权益/费用和新闻规则状态。实时记录，结束后从同一任务档案复盘。
观察和允许模拟委托分别启用；启动、暂停开仓、停止运行、平仓的含义分开，不复用模糊按钮。
停止按既有取消/确认流程收尾，报告剩余持仓和挂单；异常冻结与重启先对账规则继续生效。
跨日/异常恢复、自动换月及多任务资金分配在扩展阶段专项验证，不能仅增加“继续”按钮。

## 8. 新闻、财经日历与自动事件规则

### 8.1 页面与数据

新闻区包含快讯与有计划发布时间的财经日历；可按国家、事件类型、重要性和关联品种筛选。
展示事件名称、来源、公布时间、前值/预期/实际值（来源提供时）、更新时间及关联规则。
来源重要性与用户自己的处理等级分别保存；用户处理等级采用低/中/高/重大，可调整品种范围。
等级表达处理强度，不直接推断涨跌方向。

金十作为优先来源：官方开放平台与授权数据合作已查到；接入前需核实实际套餐、凭证、额度、
本地保存与历史使用权限。不能用网页可见或第三方抓取接口推定免费官方 API 权限。
未取得可用数据时，可使用明确标注来源的手动日历或合法导入事件验证流程；
演示数据与真实事件分开，演示事件不得悄悄驱动实际模拟任务。

记录来源事件 ID、来源等级、用户等级、关联范围、预定时间、首次见到时间、后续修订和接收时间。
UTC 保存时间，界面显示北京时间并保留来源时区；处理美国夏令时、日历改期、撤销和重复消息。
WS 更新与 HTTP 修改游标结合，连接恢复后补齐并去重；未确认的上游回放/顺序保证不能自行假设。

### 8.2 自动规则

规则选择事件/等级、适用品种/任务、事件前 X 分钟和后 Y 分钟，以及启用状态。
首版自动动作限于暂停新开仓和加仓；已有持仓的减仓、平仓及已定义保护继续执行。
不根据新闻方向自动开反向仓，不因事件自动强平。规则变化保存版本并记录操作。

暂停应作用于执行端：阻止新开仓目标继续执行，取消相关未成交开仓单并等待确认；
明确展示撤单等待及可能发生的在途成交。仅在信号函数里跳过一根柱不能满足此要求。
暂停目标不能意外等同于目标仓位为零；必须分别表达开仓许可与减仓/平仓意图。

多事件重叠采用更严格限制；改期更新窗口、撤销事件留下记录。
突发事件从本机首次获知起处理，不能假装提前知道。
规则明确选择后窗以预定时刻还是已核实的实际发布时间为基准。首版可按计划时间计算；
收到改期或延迟信息时更新/延长暂停，等待核实或人工确认。选择“等待实际发布”的规则，
必须有可核验发布状态；来源仅有理论公布时间时，不能假装已确认实际发布或自动结束等待。
新闻源断线、游标缺口、数据陈旧或时钟不可信时，启用事件保护的任务暂停新开仓，
保留减仓/平仓保护并显示原因；补齐数据、核实账户且等待新决策后才恢复，不能重放积压目标。

界面常驻显示“开仓允许/事件暂停/数据待核实”、触发事件、限制区间与恢复条件。
每次触发、取消挂单、恢复、人工覆盖都进入任务记录。初次启用规则需验证配置和事件源就绪。

### 8.3 历史回测中的事件

最新日历快照和事后修订值不等于当时可得信息。回测需使用当时已知的日程与事件版本，
并以当时接收/发布时间控制可用性；没有可靠历史版本时，仅展示事件背景，不宣称验证了新闻规则。
当前金十文档的日历历史查询限制为一年内、单次跨度不超过七天；变更记录不传游标时
默认从最早七天前返回，这不代表已确认其最长保留期。这些能力不等于完整历史逐时点档案。
先从接入后保存的增量版本积累可追溯样本，再逐项扩展历史验证。

## 9. 建议的交付批次

| 批次 | 可独立验收的交付 |
| --- | --- |
| 1 | 独立窗口、中文品种目录、自选、实时主力行情；新闻区域和任务状态位置确定 |
| 2 | 策略与参数版本、新建实验、单次回测、实际成交与原因定位、持久复盘 |
| 3 | 复制/比较实验、从实验创建模拟任务、实时状态和交易记录 |
| 4 | 授权新闻/日历接入、分级与开仓保护、数据故障处理及事件审计 |
| 扩展 | 参数批量、样本外、多品种共享资金、跨日/换月；实盘另行确定范围 |

数据对象和记录格式从批次 2 即考虑事件拦截与版本关联，避免批次 4 推倒实验结构。
金十接口授权可以并行核实，不阻塞无新闻规则的研究；事件规则仅在来源可靠且验收后启用。

## 10. 验证与实施交接

- 独立窗口完整覆盖登录、观察、实验与停止；关闭时不强杀执行过程，不遗留账户操作。
- 完成柱/预热/时区无未来数据；旧固定样例保持回归，参数实际被消费并可追溯。
- 品种/主力映射与权限状态真实，页面切换不改变运行目标。
- 同一实验重启可查看 K 线、成交与原因；信号和成交位置、价格区分明确。
- 比较不覆盖旧实验，不把失败/零交易/缺权限混淆；组合研究单独验证共享资金。
- 模拟对账、拒单、部分成交、撤单等待、断线和重启保护继续验收。
- 事件规则验证夏令时、改期/撤销、重叠、延迟、重复、断线补齐、在途成交和恢复不追旧目标。
- 日志/本机页面/实验导出中无认证凭证；凭证继续只留本机受控使用。
- 后续安装与验证仍统一走 tools/setup.ps1 / tools/check.ps1，不直接改 SDK 或绕过权限。

本稿先由用户审阅产品与行为，再编写实施计划并选择执行方式；当前未安装新桌面依赖、
接入新闻账户、改动运行代码或启用新闻交易规则。
